# 数据采集与交叉验证流程（P2 方法论）

> 目的：保证 8 城 × 26 字段的数据**可追溯、可复核、不编造**。
> 所有采集者（人或 LLM agent）必须按本流程执行并留痕。

## 流程总览

```
1. 字段定义（_schema.json）
2. 搜索定位（web_search，每字段 1-2 次查询）
3. 来源分级（T1-T4）
4. 主源确认（打开原始页面核对数字）
5. 交叉验证（按字段类型执行对应规则）
6. 写入 JSON（value + unit + source{url,title,collected_at}）
7. 待补标记（查不到就 null + "待补：去哪查"，绝不编造）
8. 版本管理（data_version +1，git commit 带字段摘要）
```

## 来源分级

| 级 | 来源 | 适用字段 |
|---|---|---|
| **T1 官方** | 统计局/人社局/医保局/公积金中心/住建局/政府公报、央行 LPR | 政策、工资、社保、公积金、落户、生育津贴 |
| **T2 准官方** | 本地宝（转官方公告）、中规院通勤报告、统计年鉴、新华网/人民网地方频道 | 通勤、医院数、空气、政策转述 |
| **T3 商业** | 58爱房/贝壳/楼盘网（房价、利率）、招聘平台年度报告 | 房价、商贷利率、岗位密度 |
| **T4 自评** | 基于 T1-T3 推算的指数（需注明基准和算法） | job_density_index、hukou_difficulty_score、cultural_facilities_index、price_to_income_ratio |

## 交叉验证规则

| 字段类型 | 规则 |
|---|---|
| **政策类**（限购/落户/补贴/公积金/生育） | **必须 2 个独立来源**：T1 官方原文 + T2 复述。一致才写 value；不一致以 T1 为准，note 说明差异 |
| **统计类**（工资/通勤/空气/医院） | T1/T2 直引优先；仅 T2 单源时 source.title 加"（待官方口径复核）" |
| **市场类**（房价/利率） | 房价：2 个平台均价互核，差异 >10% 标 note；利率：LPR+加点逻辑推算，标"实测银行报价待核" |
| **自评指数** | value 注明基准（如"深圳=100"），source.title 写"自评：基于 XX"，保证可复算 |
| **查不到** | `value: null` + `source.title: "待补：具体查询路径"`，**禁止编造** |

## 复核清单（每城完成后自查）

- [ ] 所有政策类字段有 2 个来源（T1+T2）
- [ ] 所有数字有 unit 说明（单位/口径/年份）
- [ ] 所有 source.collected_at 是采集当天日期
- [ ] 自评指数都注明了基准
- [ ] null 字段都有"待补：去哪查"
- [ ] JSON 通过 schema 结构校验
- [ ] git commit message 列出本次更新的字段和数据要点

## 已知待补字段（跨城统一处理）

| 字段 | 原因 | 计划 |
|---|---|---|
| job_density_index | 需招聘平台年度报告（猎聘/BOSS直聘人才报告） | 8 城采完后统一下载报告补 |
| unemployment_rate | 市级月度数据发布不规律 | 用省级城镇调查失业率近似 |
| medical_reimbursement_inpatient | 各市医保局待遇表格式不一 | 逐市查"基本医疗保险住院待遇" |
| cultural_facilities_index | 无统一客观源 | 用大众点评/美团"Livehouse/剧场"数量近似 |
